# 修复记录：智能轮询优化

## 问题描述
项目详细页面一直在无脑循环访问以下接口：
- `GET /api/projects/3/videos` - 获取视频列表
- `GET /api/projects/3/status` - 获取项目状态

即使没有任何下载或打标任务在进行，轮询也不会停止，造成资源浪费。

## 根本原因
1. **无条件轮询**：前端使用 `setInterval` 每 2 秒无条件轮询所有接口，不管是否有任务在进行
2. **重复请求**：之前每次轮询都会对每个视频调用详情接口获取指标，造成大量重复请求
3. **缺少状态管理**：没有根据视频的实际状态智能决定是否需要轮询

## 解决方案

### 1. 智能轮询逻辑
修改 `pages/ProjectDetail.tsx` 的轮询 `useEffect`，只在有任务进行时才启动轮询：

```typescript
// 智能轮询：只在有任务进行时才轮询
useEffect(() => {
  // 检查是否有正在进行的任务
  const hasDownloadingVideos = videos.some(v => v.status === 'downloading' || v.status === 'pending');
  const hasTaggingVideos = videos.some(v => v.ai_tagging_status === 'processing');
  
  // 如果没有任何进行中的任务，不启动轮询
  if (!hasDownloadingVideos && !hasTaggingVideos) {
    console.log('⏸️ 没有进行中的任务，停止轮询');
    return;
  }

  console.log('🔄 检测到进行中的任务，启动轮询...');
  const interval = setInterval(() => {
    loadVideos();
    loadProjectStatus();
    // 只在有打标任务时才加载标签
    if (hasTaggingVideos) {
      loadVideoTags();
    }
  }, 2000);

  return () => {
    console.log('⏹️ 清理轮询定时器');
    clearInterval(interval);
  };
}, [videos]); // 依赖 videos 状态，任务状态变化时重新评估是否需要轮询
```

**关键点：**
- 只有当存在 `downloading`、`pending` 状态的视频，或者有 `processing` 状态的打标任务时，才启动轮询
- 任务状态变化时，会重新评估是否需要轮询
- 当所有任务完成后，轮询会自动停止

### 2. 精准的标签轮询
修改 `loadVideoTags` 函数，只加载正在打标的视频：

```typescript
// 加载视频标签（只加载正在打标的视频）
const loadVideoTags = async () => {
  // 只处理正在打标的视频
  const taggingVideos = videos.filter(v => 
    v.status === 'ready' && v.ai_tagging_status === 'processing'
  );
  
  if (taggingVideos.length === 0) return;
  
  for (const video of taggingVideos) {
    try {
      const response = await videoApi.getVideoTags(video.id);
      if (response.success && response.data) {
        setVideoTags(prev => ({
          ...prev,
          [video.id]: response.data
        }));
      }
    } catch (err) {
      console.log(`无法加载视频 ${video.id} 的标签信息`);
    }
  }
};
```

### 3. 初始加载已完成的标签
添加 `loadAllVideoTags` 函数，在页面初始加载时，一次性加载所有已打标或正在打标的视频的标签信息：

```typescript
// 初始加载所有视频的标签信息
const loadAllVideoTags = async (videosData?: any[]) => {
  const videosToCheck = videosData || videos;
  const videosNeedingTags = videosToCheck.filter((v: any) => 
    v.status === 'ready' && 
    (v.ai_tagging_status === 'completed' || v.ai_tagging_status === 'processing')
  );
  
  console.log(`📋 初始加载：发现 ${videosNeedingTags.length} 个视频需要加载标签信息`);
  
  for (const video of videosNeedingTags) {
    try {
      const response = await videoApi.getVideoTags(video.id);
      if (response.success && response.data) {
        setVideoTags(prev => ({
          ...prev,
          [video.id]: response.data
        }));
      }
    } catch (err) {
      console.log(`无法加载视频 ${video.id} 的标签信息`);
    }
  }
};
```

### 4. 批量加载视频指标（前置修复）
修改后端 `backend/src/controllers/videoController.js` 的 `getProjectVideos` 接口，直接返回视频的指标数据，避免前端循环调用详情接口：

```javascript
// 获取项目的所有视频
async getProjectVideos(req, res) {
  try {
    const { project_id } = req.params;
    
    // 获取视频列表
    const videos = await VideoModel.getVideosByProject(project_id);
    
    // 获取统计信息
    const stats = await VideoModel.getVideoStats(project_id);

    // 为每个视频加载指标数据 (避免前端循环调用)
    const videosWithMetrics = await Promise.all(videos.map(async (video) => {
      const metrics = await VideoModel.getVideoMetrics(video.id);
      return {
        ...video,
        metrics: metrics
      };
    }));
    
    res.json({
      success: true,
      data: {
        summary: {
          total: parseInt(stats.total) || 0,
          downloaded: parseInt(stats.downloaded) || 0,
          downloading: parseInt(stats.downloading) || 0,
          pending: parseInt(stats.pending) || 0,
          failed: parseInt(stats.failed) || 0
        },
        videos: videosWithMetrics
      }
    });
  } catch (error) {
    console.error('获取视频列表失败:', error);
    res.status(500).json({
      success: false,
      message: '获取视频列表失败',
      error: error.message
    });
  }
},
```

## 效果对比

### 修复前
- ❌ 每 2 秒无条件轮询所有接口
- ❌ 每次轮询都对每个视频调用详情接口（如果有 10 个视频，就是 10 个额外请求）
- ❌ 即使没有任何任务在进行，轮询也不停止
- ❌ 网络面板充斥大量重复请求

### 修复后
- ✅ 只在有下载或打标任务进行时才轮询
- ✅ 视频指标数据一次性批量返回，不再循环调用详情接口
- ✅ 标签接口只调用正在打标的视频
- ✅ 所有任务完成后，轮询自动停止
- ✅ 网络请求大幅减少，控制台日志清晰

## 业务逻辑

### 视频打标队列状态管理
1. **未打标状态**：视频下载完成后，`ai_tagging_status` 为 `null`，显示"视频打标"按钮
2. **打标进行中**：用户点击打标按钮后，`ai_tagging_status` 变为 `processing`，前端开始轮询该视频的标签接口
3. **打标完成**：后端完成打标后，`ai_tagging_status` 变为 `completed`，前端停止轮询，显示标签结果和"重新打标"按钮
4. **重新打标**：用户点击"重新打标"按钮，会重新创建打标任务，`ai_tagging_status` 再次变为 `processing`

### 队列状态在数据库中的体现
- `videos` 表中的 `ai_tagging_status` 字段：`null` | `processing` | `completed` | `error`
- `videos` 表中的 `ai_tagging_progress` 字段：打标进度（0-100）
- `videos` 表中的 `ai_tagging_error` 字段：打标错误信息（如果失败）
- `video_tags` 表：存储打标结果
