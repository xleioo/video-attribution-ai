# 功能实现记录：视频打标模式切换

## 实现时间
2026-01-21

## 功能描述

在系统设置中增加了视频打标模式切换选项，支持两种打标方式：
1. **对比打标**（已实现）：根据预定义标签体系进行视频内容识别
2. **主动挖掘**（待开发）：AI 主动发现和提取视频特征

## 实现内容

### 1. 数据库变更

**文件**：`backend/src/scripts/updateDatabase.js`

在 `api_configs` 表中添加新字段：
```sql
ALTER TABLE api_configs 
ADD COLUMN tagging_mode ENUM('comparison', 'discovery') DEFAULT 'comparison' 
COMMENT '打标模式: comparison=对比打标, discovery=主动挖掘'
```

**字段说明**：
- `comparison`: 对比打标模式，使用预定义标签
- `discovery`: 主动挖掘模式，AI 自由发现特征
- 默认值：`comparison`

### 2. 后端模型更新

**文件**：`backend/src/models/apiConfigModel.js`

**修改内容**：
- `createApiConfig()`: 添加 `tagging_mode` 参数支持
- `updateApiConfig()`: 添加 `tagging_mode` 参数支持

**代码片段**：
```javascript
async createApiConfig(configData) {
  const { 
    config_name, 
    api_key, 
    api_endpoint, 
    provider = 'gemini', 
    is_active = true, 
    tagging_mode = 'comparison' 
  } = configData;
  // ... 插入逻辑
}
```

### 3. 后端控制器更新

**文件**：`backend/src/controllers/videoController.js`

**修改内容**：在 `startVideoTagging()` 方法中添加模式验证

**核心逻辑**：
```javascript
// 检查打标模式
const taggingMode = apiConfig.tagging_mode || 'comparison';

if (taggingMode !== 'comparison') {
  return res.status(400).json({
    success: false,
    message: '当前打标模式为"主动挖掘"，暂不支持。请在设置中切换为"对比打标"模式。'
  });
}
```

**业务规则**：
- 只有 `comparison` 模式才允许执行打标
- `discovery` 模式返回 400 错误并提示用户
- 未配置时默认使用 `comparison` 模式

### 4. 前端 API 服务更新

**文件**：`services/apiService.ts`

**修改内容**：
- `createApiConfig()`: 添加 `tagging_mode` 类型定义
- `updateApiConfig()`: 添加 `tagging_mode` 类型定义

**TypeScript 类型**：
```typescript
tagging_mode?: 'comparison' | 'discovery';
```

### 5. 前端设置页面更新

**文件**：`pages/Settings.tsx`

#### 5.1 状态管理
```typescript
const [taggingMode, setTaggingMode] = useState<'comparison' | 'discovery'>('comparison');
```

#### 5.2 配置加载
添加 `useEffect` 钩子，在页面加载时从数据库读取当前配置：
```typescript
React.useEffect(() => {
  const loadConfig = async () => {
    const response = await apiConfigApi.getActiveApiConfig();
    if (response.success && response.data) {
      const config = response.data as any;
      if (config.tagging_mode) {
        setTaggingMode(config.tagging_mode);
      }
    }
  };
  loadConfig();
}, []);
```

#### 5.3 配置保存
在 `handleSave()` 方法中添加 `tagging_mode` 字段：
```typescript
await apiConfigApi.updateApiConfig(id, {
  // ... 其他字段
  tagging_mode: taggingMode
});
```


## 设计决策

### 1. 为什么使用 ENUM 类型？
- 确保数据一致性
- 防止无效值
- 便于数据库查询和索引

### 2. 为什么默认值是 'comparison'？
- 向后兼容现有系统
- 对比打标功能已完全实现
- 主动挖掘功能尚在开发中

### 3. 为什么在后端验证模式？
- 安全性：防止前端绕过限制
- 一致性：确保业务逻辑统一
- 可维护性：便于未来扩展

### 4. 为什么禁用主动挖掘选项？
- 功能尚未实现
- 避免用户误操作
- 提供清晰的产品路线图
